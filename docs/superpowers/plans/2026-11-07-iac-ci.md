# IaC and CI/CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the laptop-run shell deploy scripts with a CDK app per vertical and GitHub Actions pipelines that are the only thing able to deploy.

**Architecture:** One CDK app (root `cdk.json`, `infra/app.ts`) builds a `staging` and a `prod` Stage of eight stacks each, every stack defined in the owning package's `infra/stack.ts`. A separate `bootstrap-<account>` stack, deployed once by an admin, holds the GitHub OIDC roles, a CloudFormation execution role, a permissions boundary and a CDK asset bucket per stage. Stacks use `CliCredentialsStackSynthesizer`, so CI deploys with its own narrowly scoped role and passes the stage's execution role.

**Tech Stack:** AWS CDK v2 (TypeScript, run by Node type stripping), CloudFormation L1 `CfnWebFunction*`, GitHub Actions, GitHub OIDC.

**Spec:** `docs/superpowers/specs/2026-11-07-iac-ci-design.md`

## Global Constraints

- Region `eu-central-1` for every stack. Account `644789169398`. Repo `ayhansipahi/rsc-mfe-demo`.
- Stage-owned physical names: `rsc-mfe-<stage>-<name>`. Stack names: `rsc-mfe-<stage>-<stack>` (`assets`, `account`, `orders-api`, `cart-api`, `shell`, `orders-web`, `store-web`, `edge`).
- Bootstrap-owned names never match `rsc-mfe-<stage>-*`: `rsc-mfe-gh-diff`, `rsc-mfe-gh-<stage>`, `rsc-mfe-cfn-exec-<stage>`, `rsc-mfe-boundary-<stage>`, bucket `rsc-mfe-cdk-<stage>-<account>-<region>`.
- Tags on every taggable resource: `project=rsc-mfe`, `stage=<stage>`.
- Web functions: runtime `nodejs24.x`, `TimeoutSeconds` 30, `MaxConcurrencyPerEnvironment` 64, one endpoint named `live`, `EndpointType` `HomeRegion`, `AuthType` `ApplicationManaged`, 100% weight on the stack's revision.
- Exact dependency versions (repo convention): `aws-cdk-lib` `2.275.0`, `aws-cdk` `2.1148.0`, `constructs` `10.8.1`.
- TypeScript runs through Node's type stripping (`node infra/app.ts`), no tsx: no enums, namespaces or parameter properties; relative imports end in `.ts`. If a named import from an `aws-cdk-lib/*` submodule fails at runtime, use the default import and destructure.
- Tests use `node:test` and `aws-cdk-lib/assertions`. Unit tests synth with bundling skipped: `new App({ context: { "aws:cdk:bundling-stacks": [] } })`.
- CI runs Node 24. Commits follow the repo style (`feat(infra): …`), one per task, no attribution lines.

## Review Focus

1. A pipeline run with no code change must not create new web function revisions: the asset hash comes from sources, not from build output (the build stamps the time into fragments). Test in Task 2.
2. A change under `shells/web/` must redeploy the three apps that depend on it (`file:` dependency), and only them. Test in Task 2.
3. The staging pipeline role must not be able to reach prod stacks or pass the prod execution role, and the execution role must not be able to create a role without the boundary. Test in Task 6.
4. A stage with no domain must synth and serve: no `PUBLIC_HOST`, no aliases, no passkey factor, smoke test against the CloudFront hostname. Tests in Tasks 4 and 5.
5. Fork PRs must pass CI without AWS credentials. Check in Task 7.

### Task 2: Bundling and source hash

**Files:**
- Create: `infra/bundle.ts`, `infra/bundle.test.ts`

**Interfaces:**
- Produces:
  - `function sourceInputs(pkgDir: string): string[]`: repo-relative paths whose content defines the package's build. Returns `pkgDir`, every `file:` dependency directory in its `package.json`, `package-lock.json` and `scripts`.
  - `function sourceHash(pkgDir: string): string`: sha256 over `FileSystem.fingerprint` of each input, excluding `node_modules`, `build`, `.react-router`, `infra`.
  - `function bundlePackage(pkgDir: string, outDir: string): void`:
    1. `npm run build -w <pkgDir>` at the repo root.
    2. Copy `pkgDir` into `outDir`, skipping `node_modules`, `.react-router`, `infra` and `*.test.*`.
    3. Rewrite each `file:` dependency in the copied `package.json` to an absolute `file:` path.
    4. `npm install --omit=dev --workspaces=false --install-links --no-package-lock --no-fund --no-audit` in `outDir`.
    5. `node <root>/scripts/patch-react-router.mjs` with `cwd: outDir`.
  - All paths are relative to the repo root, resolved from `import.meta.dirname`.
